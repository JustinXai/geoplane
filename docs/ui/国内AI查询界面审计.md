# 国内 AI 查询界面审计

## 审计结论

**REJECT_AND_REPLAN**

人工查询组件、写入 API 和读取 API 已实现且定向测试通过，但组件没有被任何正式三角色页面使用。因此“人工 Probe 录入、结果查看、指标和客户报告”目前对用户不可达。

## 已通过的底层证据

- 首批启用平台固定为豆包、通义千问、DeepSeek、腾讯元宝；Kimi、文心一言为预留。
- `POST /api/probes/manual-samples` 只记录 `MANUAL_SAMPLE`，按项目租户授权并持久化。
- `GET /api/probes/projects/[projectId]/manual-samples` 按可读项目授权返回真实样本。
- `GET /api/probes/options` 能按角色返回可访问项目和问题。
- `ManualProbeWorkspace` 支持人工选择平台/问题、粘贴回答、登记时间、失败原因和截图引用，并展示真实样本数量与成功/失败计数。
- 没有自动登录、Cookie 托管、批量浏览器执行或真实 Provider 调用。
- Probe 定向测试通过。

## P0 缺口

1. `src/app/ops/probes/page.tsx` 仍为能力缺口页。
2. `src/app/agency/manual-probe/page.tsx` 仍为能力缺口页，并向正式用户显示英文内部词 `Provider`。
3. `src/app/app/ai-results/page.tsx` 只显示平台名单和“列表尚未开放”，未使用已经存在的读取路由。
4. `src/components/probe-report/ManualProbeWorkspace.tsx` 没有被任何正式页面导入；这是当前最直接的可达性阻断。
5. 冻结的“查询账号、账号归属、执行人员、品牌提及、竞品提及、推荐位置、审核状态”未实现；组件自己也将前三类标注为后端缺口。
6. 核心报告中的品牌曝光率、推荐进入率、问题覆盖率、竞品声量份额、平台分布、查询成功率、内容完成量和交付完成量均未形成正式页面。当前只有样本/回答/失败三个基础计数。

## 文案与边界

- `BACKEND_CAPABILITY_GAP` 若组件挂载会直接显示给正式用户，应改为“该能力尚未开放”。
- 已管理信源引用率未自动计算，符合来源采集独立延后的边界。
- 账号与样本关联、人工标注和报告指标确无持久化能力时，应继续明确空状态，不得用前端临时状态伪造。

## 验收前必须证明

- 至少在平台和代理商正式页完成项目选择、样本录入、保存后刷新仍存在。
- 客户页可只读查看自身项目结果，不能看到其他客户。
- Agency 对未分配项目的读取和写入均返回拒绝。
- 预留平台仅显示“暂未启用”，不可提交样本。

# 国内 AI 检测结构化结果能力核验 V2

范围纠正结论：`DEFERRED_TO_INDEPENDENT_DETECTION_SYSTEM`。现有人工样本能力统一冻结为 `INDEPENDENT_DETECTION_SYSTEM_PROTOTYPE`；结构化 Observation 与检测报告属于未来独立检测系统，不再构成国内 GEO 运营与交付主系统的 P0 阻断。

## 已核实的真实能力

- `0013_china_ai_probe_runtime.sql` 的 `raw_probe_result` 是追加式原始样本表，可保存平台、问题、回答或失败事实、证据引用、观察时间和登记人。
- `PgRawProbeResultRepository` 按客户组织和项目双重范围读取；已有 PostgreSQL 测试覆盖持久化、客户隔离及禁止修改/删除。
- `metrics.ts` 只使用人工明确标注计算指标，不解析回答正文，且受管信源引用率保持不计算。
- 页面只登记人工样本，不自动登录、不调用真实平台。

## P0 阻塞项

| 能力 | 当前事实 | 为什么不能复用现有字段 |
| --- | --- | --- |
| 品牌提及与次数 | 无持久化字段/表 | `answer_text` 是原始回答，不能编码人工判断 |
| 推荐情况 | 无持久化字段/表 | 从回答正文推断会把算法结果伪装成人工事实 |
| 回答位置 | Contract 与数据库均无此事实 | `screenshot_reference` 仅是受控证据引用，不是位置字段 |
| 引用判断与引用域 | 只有自由格式证据引用 | 证据编号不等于人工判断，也没有结构化域名约束 |
| 客户效果报告 | 无可重建的标注仓储或报告快照 | 进程内计算器要求完整标注，刷新后无法重建输入 |

这些能力是人工检测结果可审核、可刷新、可交付的最低闭环，因此仍为 P0。报告筛选、趋势对比、导出和视觉图表属于 P1，必须在 P0 持久化模型完成后再实现。

## 排除的错误实现

- 不把品牌、推荐、位置或引用判断编码进 `answer_text` 或 `screenshot_reference`。
- 不把 `audit_event.metadata` 当作业务标注仓储。审计表用于行为证据和命令幂等，不具备每个回答唯一标注、字段校验、结构化查询与报告版本约束；反向解析审计元数据会混淆审计事实和业务状态。
- 不新增或修改冻结的 `0001–0017` 迁移，不调用真实平台，不启用自动登录。

## 当前正式页面边界

页面继续展示真实原始检测记录，并明确告知用户：品牌提及、推荐情况、回答位置和引用判断尚不能持久保存，因此客户效果报告暂不生成；系统不会从回答摘要推测指标。该边界由回归测试锁定。

## 后续最小解锁条件

需要经批准新增独立的追加式人工标注模型（关联 `raw_probe_result`，包含租户/项目范围、审核人、审核时间和版本），以及可从持久化标注重建的版本化报告 Read Model。该变更必须单独评审迁移、授权、不可变性、跨租户隔离和刷新持久化测试。

# P0 数据边界审计

结论：**PASS_WITH_CHANGES**。

## 已守住的边界

- 百度需求事实只能来自带文件哈希、来源定位和观察时间的 CSV/XLSX 导入；AI 扩展不产生 `OBSERVED_DEMAND`、搜索量、出价、竞争度、趋势、流量或排名。
- Probe 原始结果按客户组织和项目存储，只允许四个启用平台与 `MANUAL_SAMPLE`；失败样本不会被解释成“未提及”。
- 自动已管理信源引用率固定为 `NOT_CALCULATED`，指标必须来自人工标注并回溯到 RawProbeResult。
- 行业规则定义、规则评估、关键词证据、拓词快照、Probe 原始结果、代理商工作流与交付记录均有数据库级只追加保护。
- 0010 没有密码、Cookie、Token 或 API Key 列；正式 API 响应剔除 `secretReference`。
- `352d025` 将可注册账号限制为冻结的 4 个 AI 与 12 个内容平台，并校验 `platformCode` 与 `accountType` 匹配；该改进不等于秘密引用格式验证。
- 未发现真实客户数据、真实账号秘密、历史关键词数量或 Provider 返回内容进入本轮新增文件。

## 租户隔离

| 数据域 | 当前保护 | 审计结果 |
|---|---|---|
| 百度关键词 | 复合外键持续携带 client/project scope；路由从服务器项目解析租户 | PASS |
| AI 拓词 | 项目读取与 principal 客户范围检查；候选审核先读取服务端 scope | PASS |
| Probe | 项目读取与 principal 客户范围检查；请求体客户组织会被服务器值覆盖 | PASS |
| 账号分配 | 服务层 `canAccessClientOrganization`；DB Trigger 校验 project/client 和账号所有权 | PASS_WITH_CHANGES |
| 代理商 | Read Model 先取授权客户并过滤事实；写服务调用授权 Port | CONTRACT_PASS / RUNTIME_BLOCKED |

## 必须修正的数据边界

1. `platform_account.secret_reference` 当前只是非结构化 `TEXT`。API 虽拒绝名为 password/cookie/token/apiKey 的字段，但调用者仍能把明文放入 `secretReference`。应要求明确引用 Scheme/Pattern（例如受控凭据库引用），并在服务层与数据库双重拒绝非引用值。
2. `AccountOperationService.recordResult` 接受 `publicationReceiptId`，数据库只验证回执存在，没有验证其客户组织、项目与任务一致。必须在写入前读取回执并执行同租户、同项目检查，最好以复合外键或数据库 Trigger 加固。
3. `operatorUserId` 目前只受用户外键约束。账号分配和任务创建应验证操作员属于授权代理商/客户组织及允许的项目范围。
4. `industry_profile_pack_selection` 是当前映射而非历史评估，未配置禁止更新删除。若后续允许改选，必须以新版本/历史事件表达，不能静默覆盖已使用的 Pack 选择。

## 只追加审计说明

“只追加”适用于证据、快照、审核决定、运行结果和历史事件；账号当前状态、任务状态等业务状态可受控更新，但必须保留相应 Ledger/Audit。0010 目前仅对 usage/result 设置数据库禁止变更，状态更新依赖既有审计链，后续应补充针对授权撤销、分配撤销和任务转换的 PostgreSQL 路由测试。

# P0 数据边界审计

结论：**PASS_WITH_CHANGES**。

## 已守住的边界

- 百度需求事实只能来自带文件哈希、来源定位和观察时间的 CSV/XLSX 导入；AI 扩展不产生 `OBSERVED_DEMAND`、搜索量、出价、竞争度、趋势、流量或排名。
- Probe 原始结果按客户组织和项目存储，只允许四个启用平台与 `MANUAL_SAMPLE`；失败样本不会被解释成“未提及”。
- 自动已管理信源引用率固定为 `NOT_CALCULATED`，指标必须来自人工标注并回溯到 RawProbeResult。
- 行业规则定义、规则评估、关键词证据、拓词快照、Probe 原始结果、代理商工作流与交付记录均有数据库级只追加保护。
- 0010 没有密码、Cookie、Token 或 API Key 列；正式 API 响应剔除 `secretReference`。
- 账号平台限制为冻结的 4 个 AI 与 12 个内容平台；`secretref://` 由服务与数据库校验，发布回执由服务与 DB Trigger 校验任务范围。
- 未发现真实客户数据、真实账号秘密、历史关键词数量或 Provider 返回内容进入本轮新增文件。

## 租户隔离

| 数据域 | 当前保护 | 审计结果 |
|---|---|---|
| 百度关键词 | 复合外键持续携带 client/project scope；路由从服务器项目解析租户 | PASS |
| AI 拓词 | 项目读取与 principal 客户范围检查；候选审核先读取服务端 scope | PASS |
| Probe | 项目读取与 principal 客户范围检查；请求体客户组织会被服务器值覆盖 | PASS |
| 账号分配 | 服务层、操作员资格、任务绑定与 DB Trigger 共同校验 | PASS（待新 Migration 实际应用） |
| 代理商 | 真实 PG Port 已组合；授权客户过滤存在 | PASS_WITH_CHANGES |

## 必须修正的数据边界

1. 迁移器明确拒绝修改已应用文件，而修复直接改写 0010。必须新增 0016，否则现有数据库约束缺失且迁移复跑会 checksum 失败。
2. 代理商工作流/交付路由从 body 接收 client 与 project，却没有比较项目真实 client；0015 也无复合约束或 Trigger，两个均已授权客户之间可形成错配记录。
3. 代理商 Read Model 对缺失 Probe/拒绝事实写死 0，违反“缺失事实不得展示为真实零值”的边界。
4. `industry_profile_pack_selection` 后续改选仍应使用版本/历史事件，不能静默覆盖。

## 只追加审计说明

“只追加”适用于证据、快照、审核决定、运行结果和历史事件；账号当前状态、任务状态等业务状态可受控更新，但必须保留相应 Ledger/Audit。0010 目前仅对 usage/result 设置数据库禁止变更，状态更新依赖既有审计链，后续应补充针对授权撤销、分配撤销和任务转换的 PostgreSQL 路由测试。

## 2. 第一检查点

- B：真实资产核验、10 个 Keyword Contract 证据、Migration/Importer/Test 差距；
- C：百度关键词生产导入、需求事实、快照、标准化与人工审核包；不得启动 Source Collection Agent；
- D：在 B Contract 冻结后确认 AI 输出来源、版本与人工审核 Contract；
- E：国内平台 Registry、Manual Sample Probe、原始结果和可解释指标；
- F：跨行业 Core 复用边界、VerticalPolicyPack Contract/Loader；
- G：平台代理商客户状态机和交付闭环映射；
- H：只读核验分类、证据引用、越界实现和 P0 顺序。

第一检查点不大规模写业务代码，不修改 UI，不重复验证账户/Session/PostgreSQL/三角色权限/本地启停/备份恢复/通用文章链。

## 3. 依赖关系

- D 依赖 B 的需求来源与 Keyword Contract，但可先冻结 Port/DTO；
- F 的行业 Pack 不依赖自动信源采集；自动 `SOURCE_GROUNDING_GATE` 已冻结到未来独立系统；
- G 的关键词与效果状态分别依赖 C/D、E；当前只呈现人工 URL、引用信息与发布回执；
- UI 依赖全部 P0 Read Model 与状态机，属于 P2。

## 4. 集成门禁

每个 Agent 只提交独占范围；Agent A 按检查点即时 cherry-pick。文档检查点运行 `git diff --check` 与证据引用核验；代码检查点才运行相应 Focused Tests 和 Typecheck。全量测试只在集成点运行。

每两个代码集成检查点创建 `domestic-geo-recovery-checkpoint-<timestamp>.bundle`。任何 Migration 必须先有 Contract、兼容说明、回滚/恢复策略和测试；不得重写已通过的核心后端。

# 信源数据模型与状态机

文档级分类：`CURRENT_REBUILD_ADDITION`。这是本轮为恢复工作冻结的目标规格，不代表删除前精确模型；对应生产 runtime、migration 与状态机均为 `MISSING_REQUIRED_CAPABILITY`。

## 1. 文档状态

本文件冻结国内 GEO 信源采集与引用闭环的最小 P0 模型。它不是原系统模型的逐字恢复。

- 恢复证据确认“来源审计、知识引用、原始字节哈希、证据封存”方向存在：`RECOVERED_SPECIFIED_NOT_COMPLETED`
- 下述精确实体名与字段在恢复证据中没有完整实现：`MISSING_REQUIRED_CAPABILITY`
- 当前知识摄取、版本追加、内容寻址和出站发布回执仅作为：`REBUILT_EQUIVALENT`
- 本文新增的状态与约束是本轮冻结决策，不得回写成“恢复原样”

## 2. 术语边界

| 术语 | 冻结含义 |
|---|---|
| Source | 外部来源身份锚点，如一个网站、机构资料库或明确文件来源；不存某次抓取结果 |
| ManagedSource | 某客户项目对 Source 的受管配置、采集许可和启停状态 |
| SourceCollectionRun | 一次明确触发的采集运行；记录操作者、原因和运行结果，不承载正文 |
| RawCollectedDocument | 一次采集得到的不可变原始响应/文件及其哈希与网络元数据 |
| Publication | 外部来源发布的一篇页面/文章/文档身份；可有多个被采集版本 |
| ParsedSourceObservation | 从一个不可变 RawCollectedDocument 中解析出的可定位观察 |
| EvidenceFact | 经规范化和审核的业务事实版本 |
| Evidence | 某条观察对某个事实的支持、反驳或限定关系 |
| Citation | 本系统内容位置到 Evidence/Observation 的不可变引用 |
| PublicationReceipt | 本系统内容向外部渠道发布后的出站回执；沿用现有模型，与入站 Publication 完全分离 |

## 3. P0 数据模型

以下每张客户业务表均要求 `client_organization_id NOT NULL`、`project_id NOT NULL`，并对组织/项目建立真实外键。平台公共来源若未来需要共享，应通过单独的平台目录与客户 `managed_source` 授权关系实现，不允许把客户行写成无租户记录。

### 3.1 Source

来源身份锚点：

- `id`
- `source_kind`: `WEBSITE | FILE_REPOSITORY | MANUAL_UPLOAD | INTEGRATION`
- `canonical_locator`: 规范化域名、基础 URL 或外部来源标识
- `display_name`
- `publisher_name`（可空；未核实时不得伪造）
- `created_at`

约束：`source_kind + canonical_locator` 唯一；Source 不保存认证密钥、抓取正文或客户私有配置。

### 3.2 ManagedSource

客户项目对来源的管理关系：

- `id`, `source_id`
- `client_organization_id`, `project_id`
- `status`: `DRAFT | ACTIVE | PAUSED | ARCHIVED`
- `collection_mode`: `MANUAL_UPLOAD | MANUAL_URL | SCHEDULED`；P0 只开放前两种
- `allowed_path_rules`, `blocked_path_rules`
- `created_by_user_id`, `created_at`
- `status_changed_by_user_id`, `status_changed_at`

不得保存明文密码、Cookie 或 API Key。需凭据的来源必须引用独立秘密管理设施；当前阶段 `DEFERRED_BY_FROZEN_SCOPE`。

### 3.3 SourceCollectionRun 与事件

运行身份表 `source_collection_run`：

- `id`, `managed_source_id`
- `client_organization_id`, `project_id`
- `trigger_kind`: `MANUAL | SCHEDULED | RETRY`
- `requested_by_user_id`, `requested_at`
- `idempotency_key`

append-only 事件表 `source_collection_run_event`：

- `id`, `run_id`
- `event_type`: `QUEUED | STARTED | DOCUMENT_COLLECTED | DOCUMENT_SKIPPED | SUCCEEDED | PARTIALLY_SUCCEEDED | FAILED | CANCELLED`
- `reason_code`, `safe_message`, `occurred_at`, `actor_user_id`

运行当前状态从事件流派生，不在 run 表保存可漂移的可变状态。事件禁止 UPDATE/DELETE。

### 3.4 RawCollectedDocument

- `id`, `run_id`, `managed_source_id`, `source_id`
- `client_organization_id`, `project_id`
- `publication_id`（可空；解析出出版物身份后以追加关联记录绑定，不原地修改）
- `requested_locator`, `final_locator`
- `http_status`, `content_type`, `byte_size`
- `raw_content_hash`, `raw_storage_path`
- `etag`, `last_modified_at`（均可空）
- `collected_at`, `collected_by_user_id`

原始字节内容寻址；同一 `raw_content_hash` 可去重存储，但每次采集仍保留独立运行归属。记录禁止 UPDATE/DELETE。重定向链和响应头只保留安全白名单字段，不保存认证头与 Cookie。

### 3.5 Publication 与版本关联

入站 `source_publication`：

- `id`, `source_id`
- `canonical_locator`
- `external_publication_key`（可空）
- `title`（允许待解析）
- `first_observed_at`

不可变版本关联 `source_publication_revision`：

- `id`, `publication_id`, `raw_collected_document_id`
- `revision_number`
- `observed_published_at`（可空，不确定时不得拿采集时间代替）
- `observed_updated_at`（可空）
- `created_at`

同一 Publication 的网页变化生成新 revision；禁止覆盖历史版本。

### 3.6 ParsedSourceObservation

- `id`, `raw_collected_document_id`, `publication_revision_id`
- `client_organization_id`, `project_id`
- `observation_kind`: `CLAIM | DEFINITION | METRIC | DATE | QUOTE | CONTACT | OTHER`
- `original_text`
- `normalized_text`
- `locator_kind`: `PAGE | SECTION | PARAGRAPH | TABLE_CELL`
- `locator_value`
- `parser_name`, `parser_version`
- `observation_hash`, `observed_at`, `created_at`

观察是解析结果，不自动等于事实。每次重新解析产生新观察集合；观察禁止 UPDATE/DELETE。

### 3.7 EvidenceFact 与 Evidence

`evidence_fact` 采用版本追加：

- `id`, `fact_key`, `version_number`
- `client_organization_id`, `project_id`
- `subject_type`, `subject_key`
- `predicate`, `normalized_value`, `value_type`
- `valid_from`, `valid_to`（可空）
- `review_status`: `PENDING | CONFIRMED | DISPUTED | RETIRED`
- `reviewed_by_user_id`, `reviewed_at`（确认/争议时必填）
- `supersedes_fact_id`（可空）
- `created_at`

`evidence` 记录事实与观察的关系：

- `id`, `evidence_fact_id`, `parsed_source_observation_id`
- `relation`: `SUPPORTS | CONTRADICTS | QUALIFIES`
- `assessment_status`: `PENDING | ACCEPTED | REJECTED`
- `assessed_by_user_id`, `assessed_at`
- `created_at`

事实和证据记录均禁止 UPDATE/DELETE；修正通过新事实版本或新评估记录表达。不得由模型输出直接生成 `CONFIRMED`。

### 3.8 Citation

- `id`
- `client_organization_id`, `project_id`
- `content_subject_type`: `ARTICLE_DRAFT | CONTENT_BLOCK | DELIVERY_ITEM`
- `content_subject_id`, `content_version`
- `content_locator`
- `evidence_id`
- `evidence_fact_id`
- `parsed_source_observation_id`
- `citation_label`
- `created_by_user_id`, `created_at`
- `supersedes_citation_id`（可空）

Citation 固定到不可变内容版本和不可变观察，不允许只存 URL。删除或替换引用必须追加新版本；已交付内容的引用记录永久保留。

## 4. 状态机

### 4.1 ManagedSource

```text
DRAFT ──人工启用──> ACTIVE ──人工暂停──> PAUSED
  │                  ▲                  │
  └────人工归档────> ARCHIVED <──归档──┘
                     ▲
ACTIVE ──────────────┘
```

- 只有 `ACTIVE` 可创建采集运行。
- `PAUSED` 可由有权限人员恢复为 `ACTIVE`。
- `ARCHIVED` 为终态；恢复需创建新的 ManagedSource，不复活历史记录。

### 4.2 SourceCollectionRun

```text
QUEUED -> STARTED -> SUCCEEDED
                  -> PARTIALLY_SUCCEEDED
                  -> FAILED
QUEUED/STARTED    -> CANCELLED
```

- 状态由 append-only event 派生。
- `SUCCEEDED` 不代表所有文档有可用观察，只表示运行按计划结束。
- 重试创建新 run，使用 `trigger_kind=RETRY` 并引用原 run；不得回写失败 run。

### 4.3 原始文档与解析

```text
COLLECTED
  -> PARSED（产生一个或多个 ParsedSourceObservation）
  -> SKIPPED（格式/策略不支持）
  -> PARSE_FAILED（保留 RawCollectedDocument，允许新解析运行）
```

这里的状态也由事件/结果记录派生；RawCollectedDocument 自身始终不可变。重新解析不得修改旧观察。

### 4.4 EvidenceFact

```text
PENDING -> CONFIRMED
        -> DISPUTED
CONFIRMED -> DISPUTED
CONFIRMED/DISPUTED -> RETIRED
```

- 每次变化追加新事实版本；旧版本状态不回写。
- `CONFIRMED` 必须有明确人工审核人和时间；自动批准继续为 NO。
- 互相矛盾的观察不能被静默合并，应形成 `DISPUTED` 或并存的时效版本。

### 4.5 Citation

```text
PROPOSED -> VERIFIED -> ATTACHED
         -> REJECTED
ATTACHED -> SUPERSEDED（仅由新引用替代）
```

- `ATTACHED` 前必须校验内容版本、事实版本、观察和租户/项目完全一致。
- 已交付内容只允许追加 `SUPERSEDED` 关系，不允许删除原 Citation。

### 4.6 PublicationReceipt（现有出站状态）

保持当前实现：渠道由人工明确选择，真实会话 actor 创建 receipt，receipt 与 delivery 原子追加，禁止 UPDATE/DELETE。不得把采集完成、事实确认或 Citation 附着映射为自动发布动作。

## 5. 不变量

1. 任意 Citation 必须可回溯：`内容版本 → Citation → Evidence → EvidenceFact 版本 + ParsedSourceObservation → RawCollectedDocument → CollectionRun → ManagedSource → Source`。
2. 任意链路上的 `client_organization_id` 与 `project_id` 必须一致；跨租户引用在服务层和数据库层双重拒绝。
3. 原始字节哈希、解析观察、事实版本、证据关系、引用和发布回执均 append-only。
4. 采集时间不能冒充原文发布时间；缺失即为 null。
5. URL 不能单独作为证据；必须固定原始内容哈希与观察定位。
6. 解析器/模型只能提出观察或候选事实，不能自动产生 `CONFIRMED` 事实、自动批准或自动发布。
7. 当前默认渠道数继续为 0；信源采集不得改变发布侧不变量。

## 6. 接入现有链路的最薄边界

- `KnowledgeDocument/Version/Content`：可接收经人工选择后进入企业知识库的外部资料，但必须保存对 `raw_collected_document_id` 的来源关联。
- `KeywordQuestionMap` 与 `Opportunity`：现有知识包 id + 版本归属继续保留；P0 增加从知识版本到 Evidence/Citation 的可追溯关系，不复制业务规则。
- `ArticleBrief/ArticleDraft`：未来引用只传不可变 Citation 引用，不内联原始采集正文或 Provider payload。
- `PublicationReceipt`：完全保持现有出站模型，不与入站 Publication 共表、共枚举或共路由。

## 7. 冻结范围

- P0：人工上传、人工提交 URL、来源管理、单次采集、原始存档、解析观察、事实审核、引用附着。
- P1：受控定时采集、来源变更检测、冲突事实处理视图。
- `DEFERRED_BY_FROZEN_SCOPE`：OCR、表格抽取、需要登录的私有站点采集、自动发布、效果验证、计费、真实 Provider 自动判定。

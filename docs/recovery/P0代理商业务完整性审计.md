# P0 代理商业务完整性审计

结论：**PASS_WITH_CHANGES（生产运行阻断）**。审计对象已更新至集成 SHA `352d025`；该 SHA 的账号 Registry 增量不改变代理商运行时结论。

## 已完成的业务合同

- 工作流包含客户档案、项目档案、企业知识、账号授权、百度关键词、AI 扩展、用户问题确认、内容任务、内容审核、国内 AI Probe、报告、交付和复盘。
- 状态转换为显式白名单；每次转换要求 actor 与 reason，0015 以只追加事件保存。
- `MARK_READY` 要求报告阶段完成；`REGISTER_DELIVERED` 要求先 READY 且必须提供人工回执引用。
- 读模型只聚合 `AgencyDeliveryReadPort` 提供的事实：授权客户、项目状态、真实待办、账号异常、交付和质量计数；没有固定演示数字或 Fixture 注入。
- 代理商只能请求自身组织；平台管理员可读取平台代理商聚合。服务层写操作再次调用客户授权 Port。
- 没有计费、佣金、订阅、白标或自动发布状态。

## 生产完整性缺口

`src/runtime/agency-delivery/runtime-context.ts` 的 singleton 默认是 `null`，`getAgencyDeliveryRuntime()` 会直接抛出 `AGENCY_DELIVERY_RUNTIME_NOT_COMPOSED`。当前仅存在 `__setAgencyDeliveryRuntimeForTests`，仓库内没有：

1. `AgencyDeliveryReadPort` 的 PostgreSQL 实现；
2. `AgencyDeliveryWritePort` 的 PostgreSQL 实现；
3. `AgencyClientAuthorizationPort` 的 PostgreSQL 实现；
4. 本地/生产组合根对上述实现的装配。

因此 `portfolio`、`workflow`、`deliveries` 三条正式 API 目前只能在测试注入环境工作，不能声称已经接入真实 Read Model 或真实数据库。

## 修复验收门槛

- 从真实 agency-client assignment、project、knowledge、keyword review、content review、Probe、account ledger、delivery event 表构建 Port，所有查询必须携带 agency/client/project scope。
- Read Model 不得用缺失事实补 0 后宣称真实完成；缺失依赖应返回明确未配置/不可用状态。
- 写入 0015 前验证 agency-client assignment 为 ACTIVE，并验证 project 确属 client。
- 增加三角色真实 PostgreSQL 路由测试：未登录 401、非代理商 403、未授权客户 403、授权客户可读写、刷新后连续、跨租户零泄漏。
- 验证人工回执写入后可从真实 Read Model 读取，并确认没有自动发布或自动交付路径。

在上述门槛通过前，代理商能力只能标记为 `CONTRACT_AND_TEST_ONLY`，是 P0 完成判定的阻断项。

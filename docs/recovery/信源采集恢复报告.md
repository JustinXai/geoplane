## 2. 结论

当前系统已经具备可靠的“企业知识资料摄取”底座，也具备真实、不可变的“对外发布回执”链路；但它还不是一套信源采集与引用系统。

最关键的语义边界是：

1. 当前 `KnowledgeDocument` / `KnowledgeVersion` 解决的是客户资料入库、版本化和持久化，不等价于受管外部信源、采集批次、原始网页存档、解析观察、证据事实和内容引用。
2. 当前 `PublicationReceipt` 记录本系统内容向外部渠道发布的结果；它不等价于“被采集信源上的原始出版物（Publication）”。两者方向相反，不能复用同一实体。
3. 当前 Opportunity 只固定到知识包 id + 版本，ArticleBrief 只携带审核决定和关键词；没有从文章段落回溯到外部原文观察的引用链。
4. `ManagedSource`、`SourceCollectionRun`、`RawCollectedDocument`、`ParsedSourceObservation`、`EvidenceFact`、业务 `Evidence`、`Citation` 和入站 `Publication` 均为当前 P0 缺口。

### 4.1 当前可用采集入口

| 入口 | 分类 | 事实 |
|---|---|---|
| `POST /api/knowledge/packages/[id]/files` | `REBUILT_EQUIVALENT` | 认证、租户归属校验、base64 文件摄取、解析、版本追加、审计 |
| `POST /api/knowledge/packages/[id]/urls` | `REBUILT_EQUIVALENT` | 接收调用方已经获取的 HTML 字节；路由明确不访问网络 |
| `fetchUrlDocument` | `CURRENT_REBUILD_ADDITION` | 有 15 秒超时、2xx 与 HTML 类型检查、可注入 fetch 和无真实网络单测；当前未接到上述路由形成服务端采集入口 |
| TXT / Markdown / DOCX / PDF / HTML 解析 | `CURRENT_REBUILD_ADDITION` | 20 MiB 上限、格式识别、MIME/扩展名冲突警告、空内容/加密 PDF/解析失败分类 |
| OCR、图片、表格 | `DEFERRED_BY_FROZEN_SCOPE` | 解析器明确拒绝 OCR 和 spreadsheet；本轮不扩展 |

直接把 `fetchUrlDocument` 接到公网采集入口并不安全。当前帮助函数没有证明具备 DNS 重绑定防护、内网/环回地址阻断、重定向逐跳校验、域名许可、robots/频率策略、响应体流式上限和凭据隔离，因此只能视为可复用下载原语，不是生产级受管采集器。

### 4.2 Append-only 与归属字段

| 数据 | 当前保证 | 注意事项 |
|---|---|---|
| `knowledge_version` | 新版本追加；数据库禁止 UPDATE；含 `client_organization_id`、`project_id`、`package_id`、`document_id`、创建人 | DELETE 未被禁止，并允许随知识包/文档级联删除；不是永久原始采集档案 |
| `knowledge_snapshot` | 封存内容字段不可改，只允许标记被新快照替代；含租户、项目、包、创建人 | 可复用为“冻结版本”思想，不直接承载逐条引用 |
| `knowledge_content` | 内容寻址；数据库禁止 UPDATE/DELETE | 租户与项目字段允许同时为 NULL；P0 信源链不得沿用无归属写入方式 |
| `opportunity_validation` / `human_review_decision` | UPDATE/DELETE 均禁止；租户和项目必填 | 可复用版本追加与人工审核模式 |
| `publication_receipt` / `delivery` | UPDATE/DELETE 均禁止；租户和项目必填；一事务成对写入 | 属于出站交付，不属于入站来源采集 |

## 5. 可复用基础

1. `KnowledgeIngestionService` 的解析、哈希、内容寻址和版本追加方式可复用，但新采集链必须保留原始字节与采集元数据，不能只保存提取文本。
2. `PgKnowledgeContentStore` 的同键同内容幂等、同键不同内容拒绝和数据库不可变触发器可复用于原始采集对象存储。
3. `knowledge_snapshot`、`opportunity_validation`、`human_review_decision`、`publication_receipt` 的 append-only 模式可复用于采集运行事件、观察、事实版本与引用版本。
4. 所有现有 GEO 业务表的 `client_organization_id + project_id` 归属方式应继续用于客户/项目级采集数据。
5. 命令路由的会话派生 actor、租户从被引用对象反查、幂等键和审计写入方式可复用于未来采集命令。

## 6. P0 建议

1. 先实现最小来源链：`Source → ManagedSource → SourceCollectionRun → RawCollectedDocument → ParsedSourceObservation → EvidenceFact/Evidence → Citation`；详细冻结见《信源数据模型与状态机》。
2. 明确区分入站 `Publication` 与现有出站 `PublicationReceipt`，禁止复用表或状态枚举。
3. 所有原始文档、观察、事实、证据与引用均必须携带租户、项目、来源和版本归属；禁止无租户信源写入客户业务链。
4. 原始采集字节、解析文本、观察和事实分层存储；每层用哈希和不可变外键回指上一层。
5. Citation 必须固定到不可变观察/事实版本，不能只引用“当前 URL”或可变网页。
6. 新增服务端网络采集前先冻结 SSRF、重定向、域名许可、内容大小、速率、robots 与审计策略；未完成前保持当前“调用方提供 HTML 字节”的安全边界。

## 7. 本轮不做

- `DEFERRED_BY_FROZEN_SCOPE`：OCR、表格抽取、监测效果、自动发布、真实 Provider 调用、真实客户数据。
- 不修改现有知识、发布或权限核心；不把缺口用 Fixture 或假数据补齐。

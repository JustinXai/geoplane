# 代理商交付独立复核

复核基线：`51c7efb2d771a5eb827adb97abc9e14f50fe81ba`

复核范围：`代理商交付能力恢复矩阵.md`、`平台代理商客户状态机.md`，以及其引用的恢复源、Migration、API、DTO 和测试。未修改代码、UI 或数据库。

## 复核结论

判定：`PASS_WITH_CHANGES`。

原文正确识别了真实的客户授权、项目、知识、内容审核、回执与交付底座，也正确指出平台主管经营聚合缺失。但有四项事实边界需要修订：

1. **AI 拓词无实现证据**：本阶段指令仍明确要求默认使用 `RECOVERED_SPECIFIED_NOT_COMPLETED`；该标签仅按指令保留，不得解读成找到删除前实现，精确字段草案仍是当前新增。
2. **关键词问题映射不等于关键词确认**：当前 `KeywordQuestionMap` 和 Opportunity review 没有“真实需求/AI 假设”来源分层，也没有关键词/问题级确认记录。
3. **团队底层不等于团队能力完成**：Membership/Invitation/Session 存在，但代理商团队读取/管理 API 缺失。
4. **平台九项指标全部缺少正式聚合**：部分底层数据可重算，但当前没有以代理商为聚合根的后端 Read Model；活跃项目、异常项目和代理商质量连冻结口径也没有。

## 测试证据与限制

- `tests/runtime/agency-ops/agency-client-portfolio.test.ts` 和 `agency-project-reads.test.ts` 验证前端读侧组合与 fail-closed，但使用 fake API client；只能证明读侧逻辑，不能单独证明数据库事实。
- `tests/persistence/pg-tenancy-runtime.pg.test.ts`、`tests/runtime/commands/command-api.route.pg.test.ts` 与闭环 E2E 提供 assignment/tenant 的真实 PostgreSQL 证据。
- `tests/runtime/geo/*persistence.pg.test.ts` 与闭环 E2E 提供内容、审核、回执、交付持久化证据。
- `tests/agency-client-isolation.test.ts` 明确是 Fixture 形态测试，不能用作正式运行时指标证据。

## P0 建议

1. 先冻结九项指标口径，再建立只读 SQL/Repository 聚合和 DB-backed 测试。
2. 首批只实现可从现表重算的客户数、知识缺口、内容审核、待交付、已交付。
3. 活跃项目、异常项目必须先有业务定义；代理商质量在底层指标明确前保持 unavailable。
4. 关键词、AI 拓词、信源、效果模块按各自恢复 Contract 接入，不能用 Fixture 或零值占位。

复核后的两份文档已经把“当前真实实现”“可复用底层”“P0 缺口”和“冻结推迟项”分开，可作为后续后端 Read Model 设计输入；不能作为九项指标已经上线的证明。

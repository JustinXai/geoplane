## 1. 设计目标与边界

目标是在权威只读源到位后，为国内关键词参考资产提供“可追溯导入 → 原始观察 → 规范化 → 需求观察 → 版本快照 → 分类 → 关键词族草稿 → 人工审核包”的最小运行时，并通过稳定引用接入现有 GEO 内容机会链。

本检查点不做：

- 不创建迁移，不导入数据，不新增 API，不改变当前业务状态机。
- 不调用百度或其他外部 Provider。
- 不把 `38`、`80,361`、`71,183`、`241,083`、`3,074` 当成事实或测试常量。
- 不以 `KeywordQuestionMap`、`OpportunityFamily`、`HumanReviewDecision` 冒充十项结构。

所有下述结构当前均为 `MISSING_REQUIRED_CAPABILITY`；字段是待源格式验证的最小建议，不是恢复事实。

## 2. 建议 Contract（待源证据后冻结）

所有结构必须带 `clientOrganizationId`、`projectId` 或明确的 platform-reference 作用域；历史观察、快照、分类版本与审核决定采用追加式记录。

| 结构 | 最小职责 | 建议核心字段 | 不变量 |
|---|---|---|---|
| `KeywordReferenceSourceImport` | 一次权威源导入批次 | `id`、scope、`sourceKind`、`sourceManifestHash`、`startedAt`、`completedAt`、`status`、解析/拒绝计数 | manifest hash + scope 幂等；完成后不可修改 |
| `KeywordRawObservation` | 保存逐条原始观察 | `id`、`importId`、`sourceLocator`、`rawKeyword`、`observedAt`、`rawMetrics`、`rawRecordHash` | 不覆盖原文；同批同 record hash 去重 |
| `KeywordNormalizedForm` | 记录原始词到规范词的版本化映射 | `id`、`rawObservationId`、`normalizedKeyword`、`normalizationRuleVersion`、`createdAt` | 规则版本必填；新规则产生新记录 |
| `KeywordDiscovery` | 记录关键词如何进入项目候选池 | `id`、`normalizedFormId`、scope、`discoveryMethod`、`discoveredAt` | 来源可追溯；不能凭空生成来源 id |
| `KeywordDemandObservation` | 记录一个时间点/周期的需求指标 | `id`、`normalizedFormId`、`metricKind`、`metricValue`、`period`、`region`、`device`、`sourceSnapshotId` | 指标单位与口径必填；历史不可覆盖 |
| `KeywordReferenceSnapshot` | 封存一次可重算的参考资产版本 | `id`、`importId`、`snapshotVersion`、`manifestHash`、各类可重算计数、`sealedAt` | 计数由查询重算；封存后不可变 |
| `KeywordTaxonomyVersion` | 版本化分类体系 | `id`、scope、`version`、`status`、`parentVersionId`、`publishedAt` | 已发布版本不可原地编辑 |
| `KeywordClassificationVersion` | 版本化关键词分类结果 | `id`、`normalizedFormId`、`taxonomyVersionId`、分类引用、`evidence`、`createdAt` | 指向固定 taxonomy version；变更追加新版本 |
| `KeywordFamilyDraft` | 人工审核前的关键词族草稿 | `id`、scope、`version`、成员引用、`rationale`、`status`、`createdByUserId` | 至少一个成员；草稿不能直接成为内容机会 |
| `HumanReviewPackage` | 锁定一批关键词族草稿供人工逐项确认 | `id`、scope、`packageVersion`、项目引用、`status`、`submittedByUserId`、`submittedAt` | 不静默批准；决定必须有真人、时间与明确状态 |

建议状态保持最小：

- Import：`PENDING | VALIDATED | IMPORTING | COMPLETED | FAILED`。
- Snapshot：`DRAFT | SEALED`。
- Family Draft：`DRAFT | SUBMITTED | CHANGES_REQUESTED | APPROVED | REJECTED`。
- Review Package：`OPEN | IN_REVIEW | COMPLETED`；包完成不代表包内项目自动批准。

## 3. 与当前重建运行时的接线边界

当前实现是 `CURRENT_REBUILD_ADDITION`：

```text
KeywordQuestionMap
  → Opportunity
  → OpportunityValidation
  → HumanReviewDecision
  → OpportunityFamily
```

建议新运行时只在人工确认后输出稳定投影：

```text
KeywordReferenceSnapshot
  → KeywordClassificationVersion
  → KeywordFamilyDraft
  → HumanReviewPackage（显式人工确认）
  → 投影为项目级 KeywordQuestionMap entry
  → 复用现有 Opportunity 后续链路
```

边界规则：

1. 新模块不复制 `Opportunity` 之后的业务规则。
2. 投影必须保存 `snapshotId`、`classificationVersionId`、`familyDraftId`、`reviewPackageId` 的稳定引用；若现有 Contract 暂不能携带，先新增关联表，不把内部字段塞进 UI 文本。
3. 只有明确人工批准的关键词族项目可以进入现有机会链；不得默认批准。
4. 百度需求指标是参考证据，不直接等价为内容机会，也不能绕过企业知识 grounding。
5. 多租户和代理商授权继续使用现有 session-derived authorization；导入请求不能自报角色或 actor。

## 4. Migration 差距与建议顺序

当前最新迁移为 `0009`，以下只是未来迁移的评审顺序，不预定迁移编号：

1. `source_import` + `raw_observation`：先保证证据、幂等、拒绝记录与审计。
2. `normalized_form` + `demand_observation`：原始记录保持不可变，派生结果版本追加。
3. `reference_snapshot`：封存 manifest hash 与可重算计数。
4. `taxonomy_version` + `classification_version`：已发布/历史版本禁止更新删除。
5. `family_draft` + member 表：成员顺序稳定，至少一项由 repository 与提交事务共同保证。
6. `human_review_package` + item/decision 表：决定无默认值，批准必须有真实 reviewer FK 与显式时间。
7. 与现有 `keyword_question_map` 的投影关联表：只在前六步及人工门禁通过后加入。

数据库必须延续：UUID 主键、组织/项目外键、租户复合校验、必要唯一键、append-only trigger、审计 actor 来自 session。原始 payload 若含未知或敏感字段，不能先以整包 JSONB 无筛选落库；应在源格式审计后建立允许字段清单。

## 5. 导入器差距与最小流程

当前仓库没有百度关键词资产导入器。P0 导入器应分两阶段：

### 阶段 A：纯只读 dry-run

1. 读取 manifest 和文件，不修改源目录。
2. 计算逐文件 SHA-256、格式、编码、表头、物理行数。
3. 输出字段分布、空值、重复、无法解析记录与拒绝原因。
4. 按提供的口径重算五组规模数字；没有口径就报告 `COUNT_DEFINITION_NOT_AVAILABLE`。
5. 输出临时核验报告，不连接业务数据库。

### 阶段 B：受控导入（须另行批准）

1. 只接受阶段 A 已验证且 hash 未变化的 manifest。
2. 先创建 import batch，逐批写原始观察；每批事务可回滚。
3. 规范化、指标、分类均作为派生版本写入，不更新原始记录。
4. 重跑同 manifest 必须幂等；部分失败必须可从最后完整批次恢复。
5. 完成后由数据库查询重算计数，与 manifest 对账后才允许封存 snapshot。

## 7. P0 决策门

进入代码实现前必须同时满足：

- 权威源目录可读，且有来源说明、manifest 与逐文件 hash。
- 十项结构与源字段的映射经人工确认，没有用猜测补字段含义。
- 五组数字均能从同一份冻结资产按明确 SQL/脚本重复计算。
- 敏感字段与真实客户数据审计通过；不合规内容有明确拒绝策略。
- Migration、回滚/恢复、幂等、租户隔离、人工审核测试方案获批准。

# 平台—代理商—客户状态机

本文件是状态投影设计，不是当前已落库的一张“客户状态机”表。每个状态必须由真实记录重算；没有事实表的模块只能报告“能力未恢复”，不能生成状态或业务量 0。

## 当前可由真实记录投影的状态

| 状态 | 事实条件 | 当前分类 | 备注 |
|---|---|---|---|
| `CLIENT_ASSIGNED` | 存在 ACTIVE `agency_client_assignment` | `REBUILT_EQUIVALENT` | 代理商只可见有效授权客户 |
| `PROJECT_CREATED` | 授权客户存在 `project` | `REBUILT_EQUIVALENT` | 当前 Project 无 active/inactive 状态 |
| `KNOWLEDGE_INCOMPLETE` | 项目知识包存在未解决 `knowledge_issue` | `CURRENT_REBUILD_ADDITION` | 可由现表重算，尚无代理商聚合 |
| `KNOWLEDGE_READY` | 冻结口径建议要求知识包 `CONFIRMED`、开放问题为 0，并存在可追溯 snapshot | `CURRENT_REBUILD_ADDITION` | 三条件均有底层记录，但组合口径尚未实现为 Read Model |
| `CONTENT_IN_PROGRESS` | 存在机会、Brief 或 Draft，且尚未进入最终批准/交付 | `REBUILT_EQUIVALENT` | 需冻结多记录并存时的优先级 |
| `CONTENT_REVIEW_REQUIRED` | 存在待机会人工审核，或 Draft 门禁/ArticleApproval 未完成 | `REBUILT_EQUIVALENT` | 当前项目 review-queue 只覆盖机会审核；文章审核需另聚合 |
| `DELIVERY_READY` | 最新文章状态为 `APPROVED`，尚无完成交付 | `REBUILT_EQUIVALENT` | 渠道仍需人工选择，默认渠道为 0 |
| `DELIVERED` | 存在合规 `publication_receipt` 与 `delivery` | `REBUILT_EQUIVALENT` | 自动发布继续关闭 |

## 当前不能由真实记录生成的状态

| 建议状态 | 缺失事实 | 分类 | 当前表现 |
|---|---|---|---|
| `KEYWORD_IMPORT_REQUIRED` | 无百度关键词源导入/快照运行时 | `MISSING_REQUIRED_CAPABILITY` | 报告“关键词资产能力未恢复”，不把行数 0 当成业务状态 |
| `KEYWORD_REVIEW_REQUIRED` | 无真实需求与 AI 假设分层、关键词/问题级确认记录 | `MISSING_REQUIRED_CAPABILITY` | 通用 Opportunity review 不等价于关键词确认 |
| `SOURCE_TASK_REQUIRED` | 无信源采集任务、受管信源、逐事实引用状态 | `MISSING_REQUIRED_CAPABILITY` | 知识文件存在不等价于信源任务完成 |
| `EFFECT_REVIEW_PENDING` | 无国内 AI 平台 Probe/样本运行时 | `DEFERRED_BY_FROZEN_SCOPE` | 显示“功能规划中” |
| `EFFECT_REVIEWED` | 无四项核心比例及问题覆盖/引用域名辅助事实记录 | `DEFERRED_BY_FROZEN_SCOPE` | 不生成总分或假趋势 |

## 投影优先级

建议 Read Model 在同一项目出现多个事实时按以下顺序呈现“下一步动作”，但该顺序须在 P0 实现前冻结并测试：

1. 授权无效：项目对代理商不可见，不返回状态。
2. 开放知识问题：`KNOWLEDGE_INCOMPLETE`。
3. 未满足知识就绪组合条件：保持知识准备中，不推导关键词/内容动作。
4. 未恢复模块：返回结构化 capability unavailable，不生成伪业务状态。
5. 存在人工审核待办：`CONTENT_REVIEW_REQUIRED`。
6. 内容生产中：`CONTENT_IN_PROGRESS`。
7. 内容已批准未交付：`DELIVERY_READY`。
8. 存在完成交付：`DELIVERED`；效果模块仍独立显示规划中。

## 不变量

- 代理商只能读取 ACTIVE 分配客户；撤销分配后不得继续读取项目聚合。
- 客户确认、HumanReview 与 ArticleApproval 不自动通过。
- 没有人工选择渠道时默认渠道数为 0。
- 没有人工或明确适配器记录不得产生 PublicationReceipt。
- 业务状态必须来自 PostgreSQL 可追溯记录；页面状态和 Fixture 不能成为事实源。
- 未恢复能力使用结构化 unavailable，不使用 `0`、空数组或成功状态掩盖缺口。
- 不用单一总分替代四项核心比例；问题覆盖率和引用域名分布保持为辅助维度。

## 平台聚合边界

平台经营 Read Model 应以代理商为聚合根，只关联 ACTIVE assignment 下的客户与项目。当前仓库没有该聚合后端；组织目录和五项组织计数不能替代九项代理商经营指标。

最小查询应分别返回：

- 已实现且可重算：授权客户数、知识开放问题、内容审核待办、交付状态；
- 需先冻结口径：活跃项目、异常项目；
- 能力未恢复：关键词确认、代理商质量、AI 拓词、信源任务、效果复盘。

任何聚合成功响应都必须带口径版本或明确的计算说明；不能用 UI 自行拼接跨租户全量数据。
